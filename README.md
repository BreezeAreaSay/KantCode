# Прозрачная вакансия

Тестовое задание онлайн-отбора хакатона «КантКод». Команда **PROMPT & PRAY**.

Сервис получает вакансии Калининградской области с портала «Работа в России» и
сохраняет отчёт в JSON: какие условия работы описаны непонятно и что редактору
вакансии уточнить у работодателя.

## Для жюри за минуту

**Работает сразу после клонирования, без настроек и установки пакетов** (нужен только Python 3.11+):

```bash
git clone https://github.com/BreezeAreaSay/KantCode.git && cd KantCode
python -m transparent_vacancy check examples/kantkod_sample_vacancies.json --out report.json
python -m transparent_vacancy html --report report.json      # открыть report.html в браузере
```

Без модели отчёт строится на правилах. Чтобы подключить ИИ, достаточно одного из
трёх способов ниже. Готовый пример отчёта с ИИ лежит в `examples/sample_report.json`,
он же страницей — `examples/sample_report.html`.

**Проверить свой файл в Docker.** Положите файл в каталог `input/`, скопируйте
настройки (`cp .env.example .env`, в Windows `copy .env.example .env`) и выберите,
откуда взять модель. Отчёт появится в `reports/report.json`.

| Способ | Что сделать в `.env` | Команда |
| --- | --- | --- |
| **А. Бесплатный ключ OpenRouter** (регистрация на openrouter.ai, покупка не нужна) | вписать ключ в `TV_AI_API_KEY=` | `docker compose run --rm app check /input/ваш_файл.json --out /data/report.json` |
| **Б. Локальная модель в Docker** (ключ не нужен, первый раз скачается около 5 ГБ) | ничего | `docker compose --profile local run --rm app check /input/ваш_файл.json --out /data/report.json` |
| **В. Ollama уже установлена на машине** (`ollama pull qwen2.5:7b`) | раскомментировать `TV_AI_BASE_URL` и `TV_AI_MODEL` (способ В в файле) | `docker compose run --rm app check /input/ваш_файл.json --out /data/report.json` |

Какая модель отвечает, видно заранее: `docker compose run --rm app models`
(для способа Б — с `--profile local`).

**Без Docker:**

```bash
TV_AI_API_KEY='<ключ>' python -m transparent_vacancy check ваш_файл.json --out report.json   # способ А
python -m transparent_vacancy check ваш_файл.json --out report.json                          # Ollama на этой машине
python -m unittest discover -s tests -t .                                                    # 253 теста, без сети
```

| Что | Где |
| --- | --- |
| Обработка начинается | `transparent_vacancy/cli.py`, запуск `python -m transparent_vacancy <команда>` |
| Рабочий режим и расписание | `run` — вручную, `schedule` или `docker compose up -d` — по расписанию; это один и тот же процесс |
| Шаг ИИ | `transparent_vacancy/ai_review.py`: после правил модель ищет расплывчатые формулировки и противоречия в тексте, код проверяет её ответ |
| Модель | `nvidia/nemotron-3-ultra-550b-a55b:free` через OpenRouter; запасные — `nvidia/nemotron-3.5-lightning:free` и локальная `qwen2.5:7b` через Ollama |
| Правила | `transparent_vacancy/rules.py`: семь тем задания, работают и без модели |
| Пример отчёта | `examples/sample_report.json` по учебному примеру организаторов `examples/kantkod_sample_vacancies.json`; страницей — `examples/sample_report.html` |
| Формат отчёта | раздел [«Формат отчёта»](#формат-отчёта) |
| Дополнительный сценарий | письма работодателю: команда `letters` и кнопка на странице отчёта, пример — `examples/letters/` |

## Как это устроено

```
портал «Работа в России» (API региона 39)      локальный JSON в формате API
        │  run / schedule                               │  check
        └────────────────────┬──────────────────────────┘
                             ▼
                правила (rules.py) — всегда
                             ▼
       модель (ai_review.py) — если доступна; её ответ проверяет код
                             ▼
     отчёт JSON  →  страница HTML  →  письма работодателю
```

Проверка идёт слоями, и отчёт не зависит от того, ответила ли модель:

1. **Правила** разбирают каждую вакансию всегда. Всё, что перечислено в разделе
   [«Что проверяется»](#что-проверяется), находит обычный код.
2. **Модель** добавляет замечания, для которых правил нет: нестандартные
   расплывчатые формулировки и противоречия в свободном тексте.
3. **Если модель не ответила**, отчёт всё равно сохраняется с замечаниями
   правил, а в `meta.ai.status` сказано честно: `unavailable` или `partial`.

## Запуск

Python 3.11 или новее, сторонних пакетов нет. Если команды `python` в системе
нет (так бывает в Linux и macOS), пишите `python3`; в Windows подойдёт и `py`.
Без аргументов программа печатает готовые команды для копирования.

### Проверочный режим

Разбирает локальный JSON в формате ответов API, к порталу не обращается.

```bash
python -m transparent_vacancy check файл.json [ещё_файл.json …] --out report.json
```

- Подходит ответ списка (`results.vacancies[].vacancy`), ответ одной вакансии,
  массив таких ответов (несколько страниц в одном файле) и голый массив вакансий.
- В отчёт попадают все переданные вакансии: ограничение `TV_MAX_VACANCIES` здесь
  не действует.
- `--require-ai` завершает команду с кодом 3, если модель ответила не на все
  вакансии. Отчёт при этом всё равно сохраняется.
- `--no-ai` — только правила; `--ai-limit N` — отдать модели не больше N вакансий.

В `examples/` два входных файла: `kantkod_sample_vacancies.json` — учебный пример
организаторов (10 вакансий), `sample_vacancies.json` — наш набор (13 вакансий
региона с портала без контактов и 6 вакансий с заранее известными дефектами).

### Рабочий режим

```bash
python -m transparent_vacancy run
```

Сервис читает API региона 39 постранично (по умолчанию 100 вакансий, две
страницы по 50), разбирает вакансии и сохраняет:

- `reports/report.json` — текущий отчёт;
- `reports/last_run.json` — чем закончился последний запуск;
- `reports/cache.json` — разборы вакансий по хешу их содержимого.

**Повторный запуск.** В отчёте один результат на ID вакансии. Вакансия, которая
не изменилась, берётся из кэша: модель её заново не разбирает, результат тот же.

**Сбой источника.** Если портал недоступен, отвечает ошибкой или не возвращает
ни одной вакансии, команда пишет ошибку в лог и в `last_run.json`, завершается с
кодом 2 и не трогает `report.json`: в нём остаётся последний успешный отчёт. Сбой
на любой странице отменяет запуск целиком, чтобы отчёт по части данных не
заменил полный.

### Запуск по расписанию

Тот же процесс, что и `run`, запускается по расписанию:

```bash
python -m transparent_vacancy schedule                 # ждать срока из TV_SCHEDULE
python -m transparent_vacancy schedule --run-on-start  # сначала выполнить запуск сразу
```

`TV_SCHEDULE` — cron-выражение из пяти полей, по умолчанию `0 6 * * *` (каждый
день в 06:00 по часам машины). Другие варианты: `docker compose up -d` (сервис по
расписанию в Docker) или системный cron:
`0 6 * * * cd /путь/к/KantCode && python -m transparent_vacancy run`.

### Docker

Ничего, кроме Docker, ставить не нужно. Способы подключить модель — в таблице
[«Для жюри за минуту»](#для-жюри-за-минуту).

```bash
docker compose run --rm app models                                # какие модели отвечают
docker compose run --rm app check /examples/kantkod_sample_vacancies.json --out /data/report.json
docker compose run --rm app run                                   # рабочий режим один раз
docker compose up -d                                              # рабочий режим по расписанию
docker compose run --rm app html --report /data/report.json       # отчёт страницей
docker compose run --rm app letters --report /data/report.json    # письма работодателям
```

- Для способа Б добавляйте `--profile local` после `docker compose`: поднимется
  Ollama и один раз скачается модель `qwen2.5:7b`.
- Отчёты появляются в каталоге `reports/` рядом с `docker-compose.yml` (в
  контейнере это `/data`); свой входной файл кладите в `input/` (в контейнере `/input`).
- С видеокартой NVIDIA добавьте файл `docker-compose.gpu.yml`:
  `docker compose -f docker-compose.yml -f docker-compose.gpu.yml --profile local …`.
- В способе В, если `models` пишет «нет связи с моделью», Ollama принимает
  запросы только с самой машины: задайте `OLLAMA_HOST=0.0.0.0` (в Windows
  `setx OLLAMA_HOST 0.0.0.0`) и перезапустите Ollama.
- Ключ и локальная модель работают вместе: впишите ключ и запускайте с
  `--profile local`. Сервис сначала спросит модели OpenRouter, а когда они
  упрутся в лимит, перейдёт на локальную.

## ИИ

**Шаг, на котором работает ИИ.** После правил каждая вакансия отправляется модели
(`transparent_vacancy/ai_review.py`). Модель читает поля вакансии и возвращает
неоднозначные формулировки и противоречия в тексте с рекомендацией, что уточнить.
Её замечания попадают в отчёт с пометкой `"detected_by": "ai"`. Пропуски модель
не ищет: их надёжнее находят правила.

**Ответу модели не верят на слово.** Ответ проверяет обычный код:

- цитата замечания должна дословно быть в названном поле вакансии;
- у противоречия должны найтись оба исходных значения, и оба должны говорить об
  одном и том же: о сумме, графике, опыте, образовании, месте работы или типе
  занятости;
- неоднозначность принимается, только если в цитате есть оговорка, открытый
  перечень или оценочное слово без меры («возможны», «иногда», «по
  договорённости», «и другие», «достойная»); отключается настройкой `TV_AI_STRICT=false`;
- отбрасываются выводы о нарушении закона, цифры и фразы, которых нет в
  вакансии, и повторы замечаний правил.

**Модели.** Клиент работает с любым сервером, у которого есть OpenAI-совместимый
`/chat/completions`. Все названные модели — с открытыми весами.

| Модель | Где | Что нужно |
| --- | --- | --- |
| `nvidia/nemotron-3-ultra-550b-a55b:free` (основная с ключом) | OpenRouter | бесплатный ключ; адрес, модель и запасные подставляются сами |
| `nvidia/nemotron-3.5-lightning:free` (запасная) | OpenRouter | тот же ключ |
| `qwen2.5:7b` (основная без ключа, последняя запасная с ключом) | Ollama, локально | `ollama pull qwen2.5:7b` или профиль `local` в Docker |
| любая другая | любой совместимый сервер | свои `TV_AI_BASE_URL`, `TV_AI_MODEL`, `TV_AI_API_KEY` |

Ключ хранится только в переменной окружения или в файле `.env`, который в
репозиторий не попадает.

**Запасные модели.** Перед разбором сервис коротким запросом проверяет модели по
порядку до первой ответившей и пишет это в лог. Если модель упёрлась в лимит
посреди запуска, запрос тут же уходит следующей; занятую модель сервис не
трогает минуту и потом пробует снова, а модель с исчерпанным дневным лимитом,
неверным ключом или неизвестным именем исключается до конца запуска. Свой
список запасных задаётся в `TV_AI_FALLBACK_MODELS` через запятую: `модель` (тот
же сервер) или `модель@адрес` (другой сервер, ключ туда не отправляется).
Какая модель разобрала вакансию, видно в отчёте: `ai_model` у вакансии и
`meta.ai.models_used`.

**Лимит бесплатного ключа.** OpenRouter даёт бесплатному ключу 50 запросов к
бесплатным моделям в сутки, сброс в 00:00 UTC. Лимит общий на все бесплатные
модели. Если набор больше, сервис перейдёт на локальную модель, если она
запущена; иначе остальные вакансии получат замечания правил, а `meta.ai.status`
будет `partial`. Уже разобранные вакансии лежат в кэше: повторный запуск
отправит модели только оставшиеся.

**Скорость.** Ответ облачной модели идёт от 20 секунд до трёх минут, поэтому с
ключом запросы идут параллельно, по 8 сразу (`TV_AI_WORKERS`): 10 учебных
вакансий разбираются примерно за две минуты. Локальная `qwen2.5:7b` на
видеокарте AMD Radeon RX 7600 разобрала те же 10 вакансий за 45 секунд, на
процессоре ноутбука — за 6,5 минуты.

**Что дают модели на учебном примере организаторов.** Nemotron 3 Ultra
ответила на все вакансии во всех прогонах, в чистых вакансиях замечаний не
дала и сама находит противоречия в тексте: например, в DEMO-39-010 «опыт
разработки учебных материалов» в требованиях при нуле в поле опыта. На ней
собран пример отчёта. Небольшая локальная `qwen2.5:7b` работает надёжно, но
своих замечаний почти не добавляет: основную работу делают правила.

## Что проверяется

Семь тем: название должности, обязанности, требования, оплата, график, место
работы, тип занятости. Читаются и описание, и структурированные поля API.

Тема считается закрытой, если конкретные сведения есть хотя бы в одном поле.
Например, «гибкий график» в описании не станет замечанием, если в поле
`scheduleTypeComment` стоит «08.00 - 17.00 ПН-ПТ» или расписание вписано прямо в
поле `schedule`: «Сменный график: 2/2, 08:00–20:00». Незаполненное образование
не замечание, если в требованиях названы конкретные знания и навыки или
работодатель пишет «опыт не требуется, обучим».

| Тема (`topic`) | Пропуск | Неоднозначность | Противоречие |
| --- | --- | --- | --- |
| `title` | нет названия | общее название («Специалист») при скупом описании работы | «младший» или «стажёр» в названии и опыт от трёх лет в требованиях |
| `duties` | нет обязанностей и навыков | слишком короткое описание, ссылка на должностную инструкцию вместо обязанностей, «иные поручения», одни общие слова без единой задачи, «возможны командировки» без частоты | — |
| `requirements` | нет требований; образование не заполнено, а требования названы общими словами; не сказано об опыте | — | опыт в поле и в тексте, образование в поле и в тексте |
| `salary` | нет суммы | оплата словами без суммы, широкая вилка без объяснения | минимум больше максимума, сумма в описании вне вилки полей |
| `schedule` | нет графика | сменный, гибкий или неполный режим без расписания; расписание названо, но «возможен гибкий график» без условий; «возможны переработки», «иногда в выходные» | полный рабочий день в поле и сменный режим в описании |
| `location` | нет адреса | адрес из одного города или области; улица без номера дома; «возможна удалённая работа» без условий | работа полностью дистанционная и обязательное присутствие в офисе; в описании один город, в адресе другой |
| `employment` | нет типа занятости, и график его не подсказывает | временная работа без срока | полная занятость и неполный день, полная занятость и доля ставки |

По любой теме правила замечают и условие, отложенное «до собеседования»:
«Формат и адрес рабочего места уточняются при собеседовании», «Требования к
знаниям уточняются на собеседовании».

**Пометки.** То, что неполно, но понять условия не мешает, попадает не в
замечания, а в отдельный массив `notes`: тип занятости не заполнен, но в графике
стоит «Полный рабочий день»; название общее («Ведущий специалист» — в госорганах
это официальное название должности), но обязанности описаны подробно; в адресе
посёлок без улицы и дома.

Рекомендации говорят, что уточнить. Выводов о нарушении закона в отчёте нет,
форма собственности работодателя не определяется.

## Формат отчёта

```json
{
  "meta": { "generated_at": "…", "mode": "file", "vacancies": 10, "findings_total": 18, "notes_total": 0, "ai": { "status": "ok" } },
  "vacancies": [
    {
      "id": "DEMO-39-003",
      "url": null,
      "job_name": "Младший аналитик данных",
      "company": "Учебная организация «Балтика»",
      "ai_reviewed": true,
      "ai_model": "nvidia/nemotron-3-ultra-550b-a55b:free",
      "findings": [
        {
          "topic": "requirements",
          "topic_title": "Требования",
          "type": "contradiction",
          "type_title": "Противоречие",
          "field": "requirement.experience",
          "quote": "0",
          "problem": "Требуемый опыт указан по-разному: в поле опыта 0 (лет), в тексте — от 5.",
          "recommendation": "Уточните у работодателя, какой опыт работы действительно обязателен, и приведите оба места к одному значению.",
          "detected_by": "rule",
          "conflict": [
            { "field": "requirement.experience", "value": "0" },
            { "field": "requirement.qualification", "value": "не менее 5 лет опыта" }
          ]
        }
      ],
      "notes": []
    }
  ]
}
```

### Запись вакансии (`vacancies[]`)

На каждую входную вакансию один объект. Вакансии с одинаковым ID объединяются:
остаётся последняя по дате изменения.

| Поле | Значение |
| --- | --- |
| `id` | ID вакансии из источника; `null`, если его нет |
| `url` | ссылка на карточку (`vac_url`); `null`, если её нет |
| `job_name` | название должности |
| `company` | название работодателя |
| `ai_reviewed` | разбирала ли вакансию модель |
| `ai_model` | какая модель её разобрала; `null`, если не разбирала |
| `findings` | массив замечаний; пустой, если замечаний нет |
| `notes` | пометки для редактора, не замечания (см. [«Что проверяется»](#что-проверяется)); формат как у замечания, `type` равен `note`; в письма не попадают |

### Замечание (`findings[]`)

| Поле | Значение |
| --- | --- |
| `topic` | тема: `title`, `duties`, `requirements`, `salary`, `schedule`, `location`, `employment` |
| `topic_title` | тема по-русски |
| `type` | `gap` — пропуск, `ambiguity` — неоднозначность, `contradiction` — противоречие |
| `type_title` | вид замечания по-русски |
| `field` | поле источника; имя совпадает с путём в JSON API, например `requirement.experience` или `addresses.address[0].location` |
| `quote` | цитата или значение из этого поля; для пропуска пустая строка |
| `problem` | суть проблемы; для пропуска — каких сведений не хватает |
| `recommendation` | что именно уточнить у работодателя |
| `detected_by` | `rule` — нашло правило, `ai` — нашла модель |
| `conflict` | только для противоречия: оба исходных значения, два объекта `{"field", "value"}` |

### Сводка (`meta`)

| Поле | Значение |
| --- | --- |
| `generated_at` | время формирования отчёта |
| `mode` | `api` — рабочий режим, `file` — проверочный |
| `source` | URL источника или имена файлов |
| `vacancies_received` | сколько вакансий пришло на вход |
| `duplicates_merged` | сколько повторов по ID объединено |
| `vacancies` | сколько вакансий в отчёте |
| `vacancies_with_findings`, `findings_total` | сколько вакансий с замечаниями и сколько замечаний всего |
| `notes_total` | сколько пометок; в число замечаний не входят |
| `findings_by_topic`, `findings_by_type` | замечания по темам и по видам |
| `pages_fetched`, `source_total` | только в рабочем режиме: сколько страниц прочитано и сколько вакансий в источнике |
| `ai.status` | `ok` — модель разобрала все вакансии; `partial` — часть; `unavailable` — ни одной; `disabled` — выключена |
| `ai.base_url`, `ai.model`, `ai.fallback_models` | сервер, основная модель и запасные |
| `ai.models_checked` | итог проверки моделей перед разбором: модель → `ok` или текст ошибки |
| `ai.models_used` | сколько вакансий разобрала каждая модель |

| `ai.vacancies_failed`, `ai.vacancies_skipped` | сбои модели и вакансии, которые ей не отдавали |

## Отчёт страницей

```bash
python -m transparent_vacancy html                          # reports/report.json → reports/report.html
python -m transparent_vacancy html --report report.json     # любой отчёт → report.html рядом
```

Одна HTML-страница без сервера, данные отчёта встроены в неё: сводка, фильтры
по теме, виду замечания и тому, кто его нашёл (правило или ИИ), поиск по
должности, работодателю и ID. У вакансии с замечаниями есть кнопка «Письмо
работодателю»: она показывает готовый запрос и копирует его одним нажатием.

## Дополнительный сценарий: запрос работодателю

**Кому помогает.** Редактору вакансии: ему не нужно вручную переписывать отчёт в
письмо работодателю.

**Какие данные API использует.** ID вакансии, ссылку на карточку (`vac_url`),
название должности (`job-name`), название работодателя (`company.name`) и
значения полей, на которые ссылаются замечания.

**Какой результат выдаёт.** Черновик запроса на каждую вакансию с замечаниями:
по пункту на замечание — что сейчас написано в вакансии и что нужно уточнить.
Письмо собирается только из отчёта и новых фактов не добавляет.

```bash
python -m transparent_vacancy letters                       # письма в reports/letters/<ID>.md
python -m transparent_vacancy letters --id <ID вакансии>
```

Пример — `examples/letters/`. Те же письма есть на странице отчёта.

## Как проверяли

```bash
python -m unittest discover -s tests -t .
```

**Тесты** не ходят в сеть: портал и модель заменены локальными серверами.
Проверяются разбор форматов входа, правила по каждой теме, что найдено в каждой
из десяти учебных вакансий организаторов, отбор ответов модели и переключение
моделей, чтение двух страниц, повторный запуск, сбой портала, недоступная
модель, настройки, расписание, кэш, письма и HTML-страница. Тесты проходят на
Linux и Windows 11.

**Учебные данные.** На примере организаторов правила без модели дают 17
замечаний в шести вакансиях и ни одного в четырёх чистых; в нашем наборе
находят все шесть заложенных дефектов. Это закреплено тестами
`tests/test_training_sample.py`.

**Живые данные.** Правила прогнаны на 1000 вакансиях региона с портала, по
каждому виду замечаний выборка просмотрена вручную, шумные правила исправлены.
Итог: замечания у 223 вакансий из 1000 (284 замечания), ещё 351 сведение
вынесено в пометки. В просмотренных выборках ложных замечаний не осталось.

**Платформы и запуск.**

- Рабочий режим на портале: 100 вакансий с двух страниц; сбой источника — код 2,
  прошлый отчёт не изменился; запуск по расписанию сработал в срок.
- Docker на двух машинах с Windows 11: образ собирается, отчёт совпадает с
  запуском без Docker; со способом В модель `qwen2.5:7b` на видеокарте разобрала
  10 учебных вакансий за 45 секунд, рабочий режим на 20 вакансиях — 109 секунд.
- OpenRouter: Nemotron 3 Ultra ответила на все учебные вакансии во всех
  прогонах; переключение с модели, которая отвечала «подождите», на запасную
  проверено на настоящем сервере.

## Ограничения

- Правила осторожны: сомнительный случай они пропускают, чтобы не давать ложных замечаний.
- Качество замечаний ИИ зависит от модели: небольшая локальная модель находит меньше, чем крупная облачная.
- У бесплатного ключа OpenRouter 50 запросов в сутки; на больший набор нужна локальная модель.
- Профиль `local` (Ollama внутри Docker) проверен командой `docker compose config`; работа локальной модели с сервисом в Docker проверена способом В.
- Расписание считает время по часам машины (переменная `TZ`, в Docker — Калининград).
- На скорость работы над заданием повлияли долгое скачивание локальных моделей и слабый интернет; если интернет медленный и у вас, удобнее способ А — скачивать ничего не нужно.
