# Прозрачная вакансия

Тестовое задание онлайн-отбора хакатона «КантКод».

Сервис получает вакансии Калининградской области с портала «Работа в России» и
сохраняет отчёт в JSON: какие условия работы описаны непонятно и что редактору
вакансии уточнить у работодателя.

- **Обработка начинается здесь:** `transparent_vacancy/cli.py`, запуск `python -m transparent_vacancy <команда>`.
- **Расписание:** встроенная команда `schedule`, `docker-compose.yml` или системный cron.
- **Пример отчёта:** `examples/sample_report.json` по учебному примеру организаторов
  `examples/kantkod_sample_vacancies.json`, тот же отчёт страницей — `examples/sample_report.html`.

## Зависимости

Python 3.11 или новее. Сторонних пакетов нет: только стандартная библиотека.

Команды ниже записаны через `python`. Если в системе такой команды нет (так
бывает в Linux и macOS), пишите `python3`; в Windows подойдёт и `py`.

Для шага ИИ нужна модель с OpenAI-совместимым API. Варианты без покупки аккаунта
описаны в разделе [«ИИ»](#ии).

## Быстрый старт: проверочный режим

Проверочный режим разбирает локальный JSON в формате ответов API и к порталу не обращается.

```bash
git clone https://github.com/BreezeAreaSay/KantCode.git
cd KantCode

# 1. Модель: локальная Ollama, ключ и аккаунт не нужны
ollama pull qwen2.5:7b

# 2. Отчёт по файлу жюри
python -m transparent_vacancy check путь/к/файлу.json --out report.json --require-ai
```

Тот же запуск без скачивания модели, через бесплатную модель OpenRouter
(нужна бесплатная регистрация и ключ, покупка не нужна):

```bash
export TV_AI_BASE_URL=https://openrouter.ai/api/v1
export TV_AI_MODEL='nvidia/nemotron-3-ultra-550b-a55b:free'
export TV_AI_API_KEY='<ваш ключ>'
export TV_AI_TIMEOUT=600
python -m transparent_vacancy check путь/к/файлу.json --out report.json --require-ai
```

Именно так получен пример отчёта в `examples/`: 10 учебных вакансий, около
четырёх минут, модель ответила на все.

Команда принимает один или несколько файлов. Подходит ответ списка
(`results.vacancies[].vacancy`), ответ одной вакансии, массив таких ответов
(несколько страниц в одном файле) и голый массив вакансий. Ограничение
`TV_MAX_VACANCIES` на проверочный режим не действует: в отчёт попадают все
переданные вакансии.

`--require-ai` завершает команду с кодом 3, если модель недоступна или ответила
не на все вакансии. Без этого флага отчёт всё равно сохраняется, а в `meta.ai`
сказано, сколько вакансий модель разобрала.

Проверить на учебных данных из репозитория:

```bash
python -m transparent_vacancy check examples/kantkod_sample_vacancies.json --out report.json
```

В `examples/` два входных файла:

- `kantkod_sample_vacancies.json` — учебный пример организаторов, 10 вакансий;
- `sample_vacancies.json` — наш набор: 13 вакансий региона 39 с портала без контактов и 6 вакансий с
  заранее известными дефектами.

## ИИ

**Шаг, на котором работает ИИ.** После правил каждая вакансия отправляется модели
(`transparent_vacancy/ai_review.py`). Модель читает поля вакансии и возвращает
неоднозначные формулировки и противоречия в тексте с рекомендацией, что уточнить.
Её замечания попадают в отчёт с пометкой `"detected_by": "ai"`.

**Ответу модели не верят на слово.** Ответ проверяет обычный код:

- цитата замечания должна дословно быть в названном поле вакансии;
- у противоречия должны найтись оба исходных значения;
- неоднозначность принимается, только если в цитате есть оговорка, открытый
  перечень или оценочное слово без меры («возможны», «иногда», «по
  договорённости», «и другие», «достойная»). Так модель не может объявить
  расплывчатой обычную конкретную фразу. Отключается настройкой `TV_AI_STRICT=false`;
- отбрасываются выводы о нарушении закона, цифры и фразы, которых нет в
  вакансии, и повторы замечаний правил.

Пропуски модель не ищет: их находят правила.

**Модель и провайдер.** Клиент работает с любым сервером, у которого есть
OpenAI-совместимый `/chat/completions`. Настройки: `TV_AI_BASE_URL`,
`TV_AI_MODEL`, `TV_AI_API_KEY`.

| Способ | Настройки | Что нужно |
| --- | --- | --- |
| Локальная Ollama (по умолчанию) | `TV_AI_BASE_URL=http://localhost:11434/v1`, `TV_AI_MODEL=qwen2.5:7b` | Установить [Ollama](https://ollama.com), выполнить `ollama pull qwen2.5:7b` (4,7 ГБ). Ключ не нужен. |
| OpenRouter, бесплатная модель | `TV_AI_BASE_URL=https://openrouter.ai/api/v1`, `TV_AI_MODEL=nvidia/nemotron-3-ultra-550b-a55b:free`, `TV_AI_API_KEY=<ключ>`, `TV_AI_TIMEOUT=600` | Бесплатная регистрация на openrouter.ai и ключ. Покупка не нужна. |
| Любой другой совместимый провайдер | свои адрес, модель и ключ | — |

Обе названные модели с открытыми весами: Qwen 2.5 (Alibaba) и Nemotron 3 Ultra (NVIDIA).

**Что проверено на учебном примере организаторов** (10 вакансий, 24 ноября 2026):

| Модель | Итог |
| --- | --- |
| `nvidia/nemotron-3-ultra-550b-a55b:free` | Ответила на все вакансии в трёх прогонах подряд, от 20 секунд до трёх с половиной минут на вакансию. В четырёх чистых вакансиях замечаний не дала; сама нашла, что «Младший аналитик» не согласуется с пятью годами опыта. На ней собран пример отчёта. |
| `nvidia/nemotron-3.5-lightning:free` | Ответила на все вакансии, 20–110 секунд на вакансию, но нашла меньше и предложила одно ложное противоречие (его отсеивает проверка ответа). |
| `google/gemma-4-31b-it:free`, `google/gemma-4-26b-a4b-it:free` | Быстрые, но в день проверки бесплатный доступ отвечал «подождите» (HTTP 429) почти на каждый запрос, у 31B даже с повторами. |

Бесплатные модели делят общий лимит провайдера, поэтому ответ «подождите»
возможен в любой момент. Клиент повторяет такой запрос (`TV_AI_RETRIES`), а
ответы, которые модель уже дала, лежат в кэше: если запуск с `--require-ai`
завершился кодом 3, повторите команду, и к модели уйдут только оставшиеся
вакансии. У `nvidia/nemotron-3-ultra-550b-a55b:free` отдельный ответ занимал
больше трёх минут, поэтому для неё задан `TV_AI_TIMEOUT=600`.

Локальная `qwen2.5:7b` при разработке проверялась отдельными запросами; полный
прогон учебного примера на ней не выполнялся.

Ключ хранится только в переменной окружения или в файле `.env`, который не
попадает в репозиторий (`.gitignore`).

Локальная модель на процессоре без видеокарты разбирает одну вакансию за
десятки секунд. Чтобы проверить быстро, ограничьте число вакансий для модели:
`--ai-limit 10`. Остальные вакансии получат замечания правил и пометку
`"ai_reviewed": false`.

Без модели сервис тоже работает (`--no-ai`): в отчёте остаются замечания правил,
а `meta.ai.status` равен `disabled`.

## Рабочий режим

```bash
python -m transparent_vacancy run
```

Сервис читает API региона 39 постранично, разбирает вакансии и сохраняет:

- `reports/report.json` — текущий отчёт;
- `reports/last_run.json` — чем закончился последний запуск;
- `reports/cache.json` — разборы вакансий по хешу их содержимого.

При настройках по умолчанию это 100 вакансий: две страницы по 50.

**Повторный запуск.** В отчёте один результат на ID вакансии. Вакансия, которая
не изменилась с прошлого запуска, берётся из кэша: модель её заново не разбирает,
результат остаётся тем же.

**Сбой источника.** Если портал недоступен, отвечает ошибкой или не возвращает
ни одной вакансии, команда пишет ошибку в stderr и в `last_run.json`, завершается
с кодом 2 и не трогает `report.json`: в нём остаётся последний успешный отчёт.
Сбой на любой странице отменяет запуск целиком, чтобы отчёт по части данных не
заменил полный.

### Запуск по расписанию

Один и тот же процесс запускается вручную (`run`) и по расписанию:

```bash
python -m transparent_vacancy schedule                 # ждать срока из TV_SCHEDULE
python -m transparent_vacancy schedule --run-on-start  # сначала выполнить запуск сразу
```

`TV_SCHEDULE` — cron-выражение из пяти полей, по умолчанию `0 6 * * *`
(каждый день в 06:00 по местному времени).

Готовые конфигурации расписания:

- `docker-compose.yml` — сервис по расписанию вместе с локальной моделью: `docker compose up -d`;
- системный cron: `0 6 * * * cd /путь/к/KantCode && python -m transparent_vacancy run`.

## Настройки

Переменные окружения или файл `.env` (образец — `.env.example`).

| Переменная | По умолчанию | Что задаёт |
| --- | --- | --- |
| `TV_SOURCE_URL` | `http://opendata.trudvsem.ru/api/v1/vacancies/region/39` | URL источника |
| `TV_SCHEDULE` | `0 6 * * *` | расписание команды `schedule` |
| `TV_MAX_VACANCIES` | `100` | максимум вакансий за запуск в рабочем режиме |
| `TV_PAGE_SIZE` | `50` | размер страницы, не больше 100 |
| `TV_OUTPUT_DIR` | `reports` | каталог отчёта, статуса и кэша |
| `TV_HTTP_TIMEOUT` | `60` | секунд на один запрос к порталу |
| `TV_HTTP_RETRIES` | `3` | попыток на один запрос к порталу |
| `TV_AI_ENABLED` | `true` | использовать ли модель |
| `TV_AI_BASE_URL` | `http://localhost:11434/v1` | адрес сервера модели |
| `TV_AI_MODEL` | `qwen2.5:7b` | модель |
| `TV_AI_API_KEY` | пусто | ключ провайдера |
| `TV_AI_TIMEOUT` | `180` | секунд на один ответ модели |
| `TV_AI_RETRIES` | `3` | попыток на один запрос к модели, если сервер занят или просит подождать (429, 503) |
| `TV_AI_WORKERS` | `2` | сколько вакансий разбирать одновременно |
| `TV_AI_MAX_VACANCIES` | `0` | сколько вакансий отдавать модели за запуск, 0 — все |
| `TV_AI_STRICT` | `true` | принимать неоднозначность от модели только с признаком расплывчатости в цитате |

URL, число вакансий и каталог можно задать и ключами команды: `run --source-url … --max … --out-dir …`.

## Что проверяется

Семь тем: название должности, обязанности, требования, оплата, график, место
работы, тип занятости. Читаются и описание, и структурированные поля API.

Тема считается закрытой, если конкретные сведения есть хотя бы в одном поле.
Например, «гибкий график» в описании не станет замечанием, если в поле
`scheduleTypeComment` стоит «08.00 - 17.00 ПН-ПТ». Расписание читается и из самого
поля `schedule`, если оно вписано туда: «Сменный график: 2/2, 08:00–20:00».
Незаполненное поле образования («Не указано») не замечание, если в тексте
требований названы конкретные знания, навыки или документы.

| Тема (`topic`) | Пропуск | Неоднозначность | Противоречие |
| --- | --- | --- | --- |
| `title` | нет названия | общее название («Специалист») | — |
| `duties` | нет обязанностей и навыков | слишком короткое описание, ссылка на должностную инструкцию, «иные поручения», одни общие слова без единой задачи | — |
| `requirements` | нет требований; образование не заполнено, а требования названы общими словами; не сказано об опыте | — | опыт в поле и в тексте, образование в поле и в тексте |
| `salary` | нет суммы | оплата словами без суммы, широкая вилка без объяснения | минимум больше максимума, сумма в описании вне вилки полей |
| `schedule` | нет графика | сменный, гибкий или неполный режим без расписания; расписание названо, но «возможен гибкий график» без условий | полный рабочий день в поле и сменный режим в описании |
| `location` | нет адреса | адрес без номера дома или только населённый пункт | работа полностью дистанционная и обязательное присутствие в офисе |
| `employment` | нет типа занятости | временная работа без срока | полная занятость и неполный день, полная занятость и доля ставки |

Сверх таблицы модель находит расплывчатые формулировки и противоречия в
свободном тексте по любой из тем.

Рекомендации говорят, что уточнить. Выводов о нарушении закона в отчёте нет,
форма собственности работодателя не определяется.

## Формат отчёта

```json
{
  "meta": { "generated_at": "…", "mode": "file", "vacancies": 19, "findings_total": 24, "ai": { "status": "ok" } },
  "vacancies": [
    {
      "id": "00000000-0000-4000-8000-000000000105",
      "url": "https://trudvsem.ru/vacancy/card/…",
      "job_name": "Повар",
      "company": "ГБУЗ «Городская больница № 1»",
      "ai_reviewed": true,
      "findings": [
        {
          "topic": "schedule",
          "topic_title": "График",
          "type": "ambiguity",
          "type_title": "Неоднозначность",
          "field": "schedule",
          "quote": "Сменная работа, По графику сменности",
          "problem": "Указан сменный режим, но конкретного расписания нет…",
          "recommendation": "Уточните у работодателя длительность смены…",
          "detected_by": "rule"
        }
      ]
    }
  ]
}
```

### Запись вакансии (`vacancies[]`)

На каждую входную вакансию один объект. Вакансии с одинаковым ID объединяются:
остаётся последняя по дате изменения.

| Поле | Значение |
| --- | --- |
| `id` | ID вакансии из источника; `null`, если его нет |
| `url` | ссылка на карточку (`vac_url`); `null`, если её нет |
| `job_name` | название должности |
| `company` | название работодателя |
| `ai_reviewed` | разбирала ли вакансию модель |
| `findings` | массив замечаний; пустой, если замечаний нет |

### Замечание (`findings[]`)

| Поле | Значение |
| --- | --- |
| `topic` | тема: `title`, `duties`, `requirements`, `salary`, `schedule`, `location`, `employment` |
| `topic_title` | тема по-русски |
| `type` | `gap` — пропуск, `ambiguity` — неоднозначность, `contradiction` — противоречие |
| `type_title` | вид замечания по-русски |
| `field` | поле источника; имя совпадает с путём в JSON API, например `requirement.experience` или `addresses.address[0].location` |
| `quote` | цитата или значение из этого поля; для пропуска пустая строка |
| `problem` | суть проблемы; для пропуска — каких сведений не хватает |
| `recommendation` | что именно уточнить у работодателя |
| `detected_by` | `rule` — нашло правило, `ai` — нашла модель |
| `conflict` | только для противоречия: оба исходных значения, два объекта `{"field", "value"}` |

### Сводка (`meta`)

| Поле | Значение |
| --- | --- |
| `generated_at` | время формирования отчёта |
| `mode` | `api` — рабочий режим, `file` — проверочный |
| `source` | URL источника или имена файлов |
| `vacancies_received` | сколько вакансий пришло на вход |
| `duplicates_merged` | сколько повторов по ID объединено |
| `vacancies` | сколько вакансий в отчёте |
| `vacancies_with_findings`, `findings_total` | сколько вакансий с замечаниями и сколько замечаний всего |
| `findings_by_topic`, `findings_by_type` | замечания по темам и по видам |
| `pages_fetched`, `source_total` | только в рабочем режиме: сколько страниц прочитано и сколько вакансий в источнике |
| `ai.status` | `ok` — модель разобрала все вакансии; `partial` — часть; `unavailable` — ни одной; `disabled` — выключена |
| `ai.base_url`, `ai.model` | адрес сервера модели и модель |
| `ai.vacancies_reviewed`, `ai.vacancies_from_cache` | разобрано сейчас и взято из кэша |
| `ai.vacancies_failed`, `ai.vacancies_skipped` | сбои модели и вакансии, которые ей не отдавали |
| `ai.findings` | сколько замечаний модели попало в отчёт |
| `ai.error` | последняя ошибка модели |

## Отчёт страницей

```bash
python -m transparent_vacancy html                          # reports/report.json → reports/report.html
python -m transparent_vacancy html --report report.json     # любой отчёт → report.html рядом
```

Одна HTML-страница без сервера: список вакансий, фильтры по теме, виду
замечания и тому, кто его нашёл (правило или ИИ), поиск по должности и
работодателю. Данные отчёта встроены в страницу.

## Дополнительный сценарий: запрос работодателю

**Кому помогает.** Редактору вакансии: ему не нужно вручную переписывать отчёт в
письмо работодателю.

**Какие данные API использует.** ID вакансии, ссылку на карточку (`vac_url`),
название должности (`job-name`), название работодателя (`company.name`) и
значения полей, на которые ссылаются замечания.

**Какой результат выдаёт.** Черновик запроса в Markdown на каждую вакансию с
замечаниями: по пункту на замечание — что сейчас написано в вакансии и что
нужно уточнить.

```bash
python -m transparent_vacancy run       # отчёт по данным API региона 39
python -m transparent_vacancy letters   # письма в reports/letters/<ID>.md
python -m transparent_vacancy letters --id <ID вакансии>
```

Письмо собирается только из отчёта и новых фактов не добавляет. Пример:
`examples/letters/`.

## Проверки

```bash
python -m unittest discover -s tests -t .
```

Тесты не ходят в сеть: портал и модель заменены локальными серверами.
Набор проходит по всем модулям:

- разбор форматов входа, в том числе учебного примера организаторов;
- правила по каждой теме и то, что найдено в каждой из десяти учебных вакансий;
- отбор ответов модели и клиент модели: ключ, сбои сервера, ответ не в формате JSON;
- источник: две страницы, сбой на любой странице, ошибка внутри успешного ответа;
- командная строка: рабочий и проверочный режимы, ключи запуска, коды выхода,
  повторный запуск на тех же данных, сбой портала, недоступная модель;
- настройки и файл `.env`, расписание, кэш разборов, письма и HTML-страница.

- Правила осторожны: сомнительный случай они пропускают, чтобы не давать ложных замечаний.
- Качество замечаний ИИ зависит от модели. Небольшая локальная модель находит меньше, чем крупная облачная.
- Расписание считает время по часам машины (переменная `TZ`).
- `docker-compose.yml` написан, но при разработке не запускался: Docker на машине разработки не было.
- На скорость работы над заданием повлияли долгое скачивание локальных моделей (одна `qwen2.5:7b` весит 4,7 ГБ) и слабый интернет. Если интернет медленный и у вас, для шага ИИ удобнее способ с OpenRouter из раздела [«ИИ»](#ии): скачивать ничего не нужно.
